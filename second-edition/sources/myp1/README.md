## Directory map

| Path | Purpose |
|---|---|
| `manuscript/chapter-NN.source.html` | Editable chapter manuscripts. Placeholders pull exercises, figures and answers from the shared data/build pipeline. |
| `data/chapter-NN.exercises.json` | Single source of truth for each chapter’s questions, answers, student-facing reasoning, tiers, verification checks and provenance. |
| `data/chapter-NN.layout.json` | Chapter-specific answer-page grouping. Chapter 1 currently uses the builder’s default answer layout. |
| `diagrams/*.svg` | Generated editable SVG teaching diagrams. Regenerated by the build from `tools/diagrams.mjs`, `tools/diagrams-ch02.mjs` and `tools/diagrams-extra.mjs`. |
| `styles/book.css` | A4 book typography, palette, page geometry, exercise/answer styles. |
| `tools/` | Node build, preview server, layout QA, PDF export and mathematical QA scripts. This directory was previously named `build/`; the rename avoids sandbox snapshot rules that exclude directories named `build`. |
| `tools/content/chapter_NN.py` | Authoring plans for Chapters 3–10: section text, worked examples, practice, investigations, applications, assessment tasks and independent verification expressions. |
| `tools/author.py` | Regenerates the editable manuscript HTML, exercise JSON and answer layout JSON from the content plans. |
| `answers/` | Reserved for answer-source notes. Answers are generated from the exercise JSON to prevent question/answer drift. |
| `fullbook/` | Assembler that binds all ten chapters, front matter, contents and end matter into the single A4 coursebook PDF (`fullbook/README.md`). |
| `../../qa/myp1/` | Layout, PDF and mathematical QA reports plus contact-sheet renders. |
| `../../qa/myp1/fullbook/` | Assembled-book QA (`book-qa.json`, page map) and renders of inspected pages. |

## Build and QA

Requires Node.js ≥ 22 and Python 3 with PyMuPDF/Pillow for post-export QA.

```bash
cd second-edition/sources/myp1/tools
npm ci

# Chapters 3–10: regenerate editable sources from authoring plans, then build.
python author.py 3 4 5 6 7 8 9 10
npm run build -- 3      # generates diagrams, HTML and answer pages
npm run check -- 3      # Paged.js layout QA in headless Chromium
npm run export -- 3     # writes ../../../exports/myp1/MYP1-Chapter-03-Revision-Proof.pdf
npm run preview         # static preview server on PORT (default 4173)

# Post-export PDF QA (from the tools directory)
PYTHONPATH=/path/to/pymupdf python qa_pdf.py 3

# Independent mathematical QA
python qa_math.py             # Chapter 1
python qa_math_ch02.py        # Chapter 2
python qa_math_chapters.py    # Chapters 3–10
```

### Sandbox Chromium note

`@sparticuz/chromium` needs its bundled Amazon Linux libraries in this Debian sandbox. The helper sets `AWS_EXECUTION_ENV=nodejs22.x` before import so the libraries are extracted. If a stale `/tmp/chromium` prevents library extraction, remove it and retry. Do not rely on Playwright browser CDN downloads in this environment.

## Editorial and QA principles

- Questions and answers render from the same JSON.
- Mathematical QA recomputes numeric results independently rather than trusting stored answer strings.
- Layout QA checks expected page count, split/missing pages, overflow, raw placeholders/LaTeX and KaTeX errors.
- PDF QA checks page count, embedded fonts, question/answer pairing and renders pages for visual inspection.
- Classroom datasets are explicitly labelled simulated. Real data would require provenance.
- MYP assessment uses **Criterion**, not “Category”. ATL statements use the required wording: “In order for a student to… students must…”.

## Known limitations

- The per-chapter proofs are revision proofs; the assembled volume in `../../exports/myp1/` is the combined book (front matter, continuous pagination, end matter).
- The PDFs are A4 and suitable for proofing/print review; final commercial print production would still need any required bleed/crop marks and printer-specific colour settings.
- The repository did not contain a separate school curriculum overview, so scope is anchored to the verified first-edition embedded planning material.
